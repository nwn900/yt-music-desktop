# YouTube Music Desktop

Native Windows wrapper for [music.youtube.com](https://music.youtube.com) built
with Rust + Tauri 2 + WebView2. Adds the things the browser tab doesn't give you:
hardware media-key control, system tray with hide-to-tray, mini-player, and
in-app Google login persistence.

Based on patterns from [nwn900/ChatGPTDesktopApp](https://github.com/nwn900/ChatGPTDesktopApp),
minus its bugs (UA spoofing, broken remote-page IPC) and ChatGPT-specific cruft
(notifications, downloads, Stripe auth hosts).

## Features

- **In-app Google login** — cookies persist in WebView2's profile folder.
- **System media controls (SMTC)** — hardware media keys, taskbar flyout, and
  Bluetooth headset controls drive YTM. Track info + album art surface
  system-wide.
- **Tray with hide-to-tray** — closing the window keeps audio alive.
- **Mini-player** — secondary frameless window with transport controls and a
  thin progress bar.
- **Autostart** — toggleable from the tray; on first start, the app
  launches minimized.
- **Single-instance** — launching again brings the existing window forward.

## Build & run

Prereqs: Rust stable (MSVC) toolchain, Microsoft C++ Build Tools, WebView2
runtime (built into Windows 11 / shipped via Edge).

```bash
# Dev (hot-reload frontend, debug Rust)
cargo tauri dev

# Release (NSIS installer + raw exe)
cargo tauri build
```

Output:

- `src-tauri/target/release/yt-music-desktop.exe` — standalone binary
- `src-tauri/target/release/bundle/nsis/YouTube Music_0.1.0_x64-setup.exe`
  — installer

The `vswhom-sys` local patch is mandatory on the VS 2026 / MSVC 14.50 toolchain
(see `local-patches/README.md`); `cargo tauri build` works unchanged because
the patch is referenced from `[patch.crates-io]` in `Cargo.toml`.

## Architecture

### Navigation allowlist

`src-tauri/src/main.rs` exposes the 9 hosts the YTM/Google stack actually
touches (`music.youtube.com`, `youtube.com`, `www.youtube.com`,
`accounts.google.com`, `google.com`, `googleusercontent.com`, `gstatic.com`,
`googleapis.com`, `ytimg.com`) plus blob: inner-host and about:blank. Anything
else opens in the system browser via `open::that_detached` and the webview
navigation is blocked — never silently killed.

### Browser args

wry replaces its default `--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection`
when you set `additional_browser_args`, so we re-append those plus:

- `--autoplay-policy=no-user-gesture-required` — restore playback after restart
- `--disable-background-timer-throttling` — keep the bridge alive when the
  window is hidden (close-to-tray)
- `--disable-renderer-backgrounding`
- `--disable-features=...,OverlayScrollbarFlashAfterAnyScrollUpdate` — fix
  scroll freeze after focus transitions

### Playback bridge (the new part)

`src-tauri/src/bridge.js` is injected on every page load. It polls the YTM
`ytmusic-player-bar` at 500 ms and 1 Hz position while playing; on any change
(title, byline, artwork, playing/duration/position) it invokes the Rust
`media_update` command. All selectors live in one `SELECTORS` const so a
YTM DOM redesign is a one-place patch.

Rust diffs the state and only touches souvlaki when something actually
changed. Track artwork is forwarded to SMTC as a remote HTTPS URI — souvlaki
calls `RandomAccessStreamReference::CreateFromUri` directly, no local download.

SMTC button events (Play / Pause / Next / Previous / SetPosition) come back
through Rust and re-eval into the main webview: they click YTM's own
`#play-pause-button`, `.next-button`, `.previous-button` or set
`video.currentTime`. YTM is the source of truth; the wrapper just relays.

### Tray & lifecycle

Tray menu: **Open YouTube Music**, **Mini player**, **Launch at startup**
(checkbox), **Quit**. Left-clicking the icon opens the main window. Closing
the main window calls `prevent_close` + `hide`; only the tray's **Quit**
sets `IS_QUITTING` and exits for real. Single-instance launches focus the
existing window.

The autostart plugin writes a `Run` registry key (HKCU); on next Windows
boot the app launches minimized (the `app.autolaunch().is_enabled()` check
in `setup`).

## Smoke checklist

Run after a fresh build:

- [ ] **Login persists**: sign in to Google inside the app, close + reopen,
  stay signed in.
- [ ] **Playback + media keys**: play a track; press hardware Play/Pause and
  Next/Previous (laptop or Bluetooth headset). Taskbar flyout shows
  title/artist/artwork.
- [ ] **Close-to-tray keeps audio**: close the main window with X; audio
  keeps playing. Tray icon stays. Click the tray icon to reopen.
- [ ] **Mini-player sync**: toggle **Mini player** from tray; artwork /
  title / artist / progress bar match the main window. Transport buttons
  drive the main window.
- [ ] **Autostart**: toggle **Launch at startup** in the tray; check
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` for
  `yt-music-desktop`. Reboot; app launches minimized-to-tray, music resumes.
- [ ] **Restart-resume**: with autoplay paused, exit the app, reopen, log
  in. `--autoplay-policy=no-user-gesture-required` should let YTM auto-
  resume the last session.

## Risks / known limitations

- **YTM DOM drift** — all selectors live in `src-tauri/src/bridge.js`'s
  `SELECTORS` const. A redesign is a one-place patch.
- **Google login heuristics** — WebView2 reports genuine Edge (no UA
  spoof). If Google flags it, see `media_update` in `smtc.rs` for the
  verification chain.
- **SMTC init failure** — logged, app keeps running, media keys just don't
  work.
- **Mini-player position** — drives a 1 Hz local interpolation; the
  `media-state` event delivers real position when anything else changes.
